## Manual installation of ST proprietary tools

ST tools require a free account at [st.com](https://www.st.com) and license acceptance; they are not redistributable, so 100% automation is impossible.

**Tip**: if you download the installer to `~/Downloads/` before re-running `./bootstrap.sh 04-embedded`, the script will detect the file and run the install for you.

### STM32CubeIDE (integrated Eclipse IDE)

1. Download from https://www.st.com/en/development-tools/stm32cubeide.html (the **Linux Generic Installer** or **Debian Linux Installer** variant).
2. Place the `st-stm32cubeide_*.sh` file in `~/Downloads/`.
3. Re-run `./bootstrap.sh 04-embedded` — or manually:
   ```bash
   chmod +x ~/Downloads/st-stm32cubeide_*.sh
   sudo ~/Downloads/st-stm32cubeide_*.sh
   ```

### STM32CubeProgrammer (universal ST flashing tool)

1. Download from https://www.st.com/en/development-tools/stm32cubeprog.html (Linux).
2. Place the `.zip` in `~/Downloads/`.
3. Re-run the script — or manually:
   ```bash
   cd $(mktemp -d)
   unzip ~/Downloads/en.stm32cubeprg-lin-*.zip
   chmod +x SetupSTM32CubeProgrammer-*.linux
   ./SetupSTM32CubeProgrammer-*.linux
   ```
4. Add the binary to PATH (usually `/opt/st/stm32cubeprogrammer/bin/`):
   ```bash
   echo 'export PATH="/opt/st/stm32cubeprogrammer/bin:$PATH"' >> ~/.zshrc
   ```

### STM32CubeMX (configuration code generator)

Now bundled inside STM32CubeIDE. Standalone version: https://www.st.com/en/development-tools/stm32cubemx.html (same procedure as CubeProgrammer).

## Typical workflows

### Arduino (pure CLI)

```bash
arduino-cli board list                              # which board on which port?
arduino-cli sketch new MyProject                    # new project
arduino-cli compile --fqbn arduino:avr:uno MyProject
arduino-cli upload  --fqbn arduino:avr:uno -p /dev/ttyACM0 MyProject
arduino-cli monitor -p /dev/ttyACM0 -c baudrate=115200
```

### STM32 (open-source chain, no ST IDE)

```bash
# Compilation (Makefile generated by CubeMX, or hand-written CMake)
make

# Flash via ST-Link (stlink-tools)
st-flash write build/firmware.bin 0x08000000

# Or via OpenOCD
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg \
    -c "program build/firmware.elf verify reset exit"

# Debug
arm-none-eabi-gdb build/firmware.elf
(gdb) target extended-remote :3333    # OpenOCD listens here
```

### Quick serial console

```bash
picocom -b 115200 /dev/ttyACM0   # Ctrl-A Ctrl-X to quit
# or
minicom -D /dev/ttyACM0 -b 115200
```

### Linux kernel — typical workflow

**Important**: `arm-none-eabi-gcc` (used for STM32 bare-metal) **cannot** compile a Linux kernel. You need a Linux toolchain (`aarch64-linux-gnu-gcc`, `arm-linux-gnueabihf-gcc`), installed by `kernel.sh`.

```bash
# Native x86_64 build
make defconfig
make -j$(nproc)

# ARM64 cross build (RPi 4/5, most modern SoCs)
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- defconfig
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- -j$(nproc)
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- Image dtbs modules

# ARM32 cross build (BBB, RPi 1/2/3 32-bit)
make ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- multi_v7_defconfig
make ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- -j$(nproc) zImage dtbs modules
```

### Quick custom kernel boot — virtme-ng

`virtme-ng` (`vng`) launches a VM reusing the host rootfs and your kernel build, with no image step. Ideal for iteration.

```bash
cd ~/linux                    # your kernel checkout
make -j$(nproc)
vng -r .                      # boot the current build directly
vng -r . --user $USER         # with your user account
vng -r . -- ./tools/testing/selftests/run_kselftest.sh  # run kselftest
```

### Kernel tracing and debug

```bash
# perf — profiling
sudo perf record -g -- ./my_program
sudo perf report

# ftrace via trace-cmd
sudo trace-cmd record -p function_graph -l 'do_sys_*'
sudo trace-cmd report
kernelshark trace.dat         # GUI

# bpftrace — DTrace-style dynamic observability
sudo bpftrace -e 'tracepoint:syscalls:sys_enter_open* { @[comm] = count(); }'

# crash dump analysis
sudo crash /usr/lib/debug/boot/vmlinux-$(uname -r) /var/crash/.../vmcore
```

### Static analysis / code verification

```bash
make C=1                              # sparse on modified files
make C=2                              # sparse on everything
make coccicheck MODE=report           # coccinelle, semantic patches
scripts/checkpatch.pl --strict patch.diff   # LKML style rules
```

### LKML patch workflow

```bash
# One-time configuration of git send-email
git config --global sendemail.smtpserver smtp.example.com
git config --global sendemail.smtpuser  your.email@example.com

# Prepare a series
git format-patch -3 --cover-letter --thread -o /tmp/patches/
# Edit /tmp/patches/0000-cover-letter.patch (subject + description)
scripts/checkpatch.pl /tmp/patches/*.patch
scripts/get_maintainer.pl /tmp/patches/0001-*.patch  # list of recipients
git send-email --to=... --cc=... /tmp/patches/

# b4: fetch a series from lore.kernel.org
b4 am https://lore.kernel.org/linux-can/...   # downloads the mbox
b4 shazam <message-id>                        # download + git am in one shot
```

### NFS + TFTP workflow for embedded kernel development

Classic pattern to iterate quickly without flashing the target: the bootloader (U-Boot) fetches `uImage` + DTB over TFTP from your workstation, and the kernel mounts its rootfs over NFS, also from your workstation. You rebuild, reboot the target, instant feedback.

Services are installed but **disabled** by default (no network listening at boot). To enable a work session:

```bash
sudo systemctl start nfs-kernel-server tftpd-hpa
```

**Minimal setup on the workstation:**

```bash
# TFTP directory (where the bootloader fetches uImage/dtb)
sudo mkdir -p /srv/tftp
sudo cp arch/arm64/boot/Image /srv/tftp/
sudo cp arch/arm64/boot/dts/<vendor>/<board>.dtb /srv/tftp/

# NFS rootfs (what the kernel will mount as /)
sudo mkdir -p /srv/nfs/rootfs
# ... extract a rootfs (Yocto, Debian via debootstrap, Buildroot…)

# NFS export (edit /etc/exports)
echo '/srv/nfs/rootfs 192.168.1.0/24(rw,no_root_squash,no_subtree_check)' \
    | sudo tee -a /etc/exports
sudo exportfs -ra
```

**U-Boot config on the target side** (example):

```
=> setenv ipaddr 192.168.1.100
=> setenv serverip 192.168.1.10
=> setenv bootargs 'root=/dev/nfs nfsroot=192.168.1.10:/srv/nfs/rootfs,vers=4 rw ip=dhcp'
=> tftp 0x80080000 Image
=> tftp 0x83000000 board.dtb
=> booti 0x80080000 - 0x83000000
```

**Security note**: `no_root_squash` is dangerous outside an isolated environment — only use it on a physically isolated dev network.

### Host-side I2C/SPI

For debugging I2C sensors with a USB-I2C adapter (Aardvark, FT232H…):

```bash
sudo i2cdetect -l                # list buses
sudo i2cdetect -y 1              # scan bus 1 (0x03 to 0x77)
sudo i2cdump -y 1 0x48           # dump a device's registers
sudo i2cset -y 1 0x48 0x00 0xAB  # write 0xAB to register 0x00
```

With the `i2c` group membership (set up by the script), `sudo` is no longer required after re-login.

### Direct SPI flash (BIOS, U-Boot)

```bash
# Chip detection with a USB programmer (CH341A, Bus Pirate…)
sudo flashrom -p ch341a_spi
# Backup before flashing
sudo flashrom -p ch341a_spi -r backup.bin
# Flash
sudo flashrom -p ch341a_spi -w new_image.bin
```

### Useful debug configs

Enable in `make menuconfig` based on your needs:

| Symbol                       | Why                                                |
|------------------------------|----------------------------------------------------|
| `CONFIG_DEBUG_KERNEL=y`      | Enables most debug options                         |
| `CONFIG_DEBUG_INFO=y`        | DWARF symbols — required for gdb, perf, crash      |
| `CONFIG_DEBUG_INFO_BTF=y`    | BTF — required for modern eBPF (uses `pahole`)     |
| `CONFIG_KASAN=y`             | KernelAddressSanitizer (use-after-free, OOB)       |
| `CONFIG_LOCKDEP=y`           | Lock validation                                    |
| `CONFIG_FTRACE=y`            | Tracing infrastructure                             |
| `CONFIG_GDB_SCRIPTS=y`       | gdb helpers (`lx-*` commands)                      |

## Why permissions matter

After your first `bootstrap.sh`, you must **log out and back in** (or reboot) for your group memberships (`dialout`, `plugdev`, `i2c`, `wireshark`) to take effect. Without this:
- `arduino-cli upload` won't see `/dev/ttyACM*`
- `st-flash` will return "permission denied"
- `openocd` won't be able to open the ST-Link probe

Verification:
```bash
groups | grep -E '(dialout|plugdev|i2c|wireshark)'
```
